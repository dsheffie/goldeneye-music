# demo

N64 ROMs used to exercise the emulator, and one meant to be published.

They are built with [libdragon](https://github.com/DragonMinded/libdragon), whose code and
open IPL3 boot block are public domain, so a ROM built here contains no Nintendo code.
`Dockerfile` pins the toolchain: `docker build -t gemusic-demo-toolchain .` once, then
`make` in any subdirectory.

| | what it is |
|---|---|
| `supersaw/` | **publishable.** A JP-8000-style supersaw: seven detuned saws per chord tone through libdragon's mixer, a synthesized kick, gated sixteenths and a sidechain pump. Wavetables are additive harmonic sums generated by `mkwaves.py`; the riff was written for this demo. Nothing in it comes from anywhere else. |
| `rspprobe/` | Learns what an RSP instruction does by running it. Fills memory with eight distinct markers, executes one patchable instruction against a zeroed register group, and dumps the result -- a data-movement instruction reveals its whole permutation in one run. This is how `ltv` was confirmed. |
| `autoplay/` | **test fixture.** Boots straight into playing an XM module, no display or controller. |
| `vadpcm/` | **test fixture.** Same, for a VADPCM sample -- the path that needs `ltv`. |

`autoplay` and `vadpcm` play libdragon's own example music. libdragon's *code* is public
domain; those compositions and samples belong to their authors and are not redistributed
here, so their `assets/` directories are deliberately empty. To build them, copy an asset
in yourself:

    cp path/to/libdragon/examples/audioplayer/assets/kamel.xm  autoplay/assets/
    cp path/to/libdragon/examples/mixertest/assets/monosample8.wav vadpcm/assets/

`supersaw` needs nothing copied -- `make` runs `mkwaves.py` to generate its wavetables.

Run any of them under the emulator with `gemusic/tests/n64_boot <rom.z64> [insns] [out.wav]
[buffers]`, which boots from the ROM's own IPL3 and captures what the audio interface is
handed.
